# 3.4.3.3 Sequence Diagram — Timetable Generation Request

**Scenario:** Timetable Officer generates a department timetable via the Shedulex web interface.

## Primary Sequence — GA Timetable Generation

```mermaid
sequenceDiagram
    autonumber
    actor Officer as Timetable Officer
    participant UI as Vue 3 Frontend<br/>(:5173)
    participant Kong as Kong API Gateway<br/>(:8000)
    participant Auth as auth-service<br/>(:5001)
    participant TT as timetable-engine<br/>(:5002)
    participant GA as GA Engine<br/>(app/ga/)
    participant DB as PostgreSQL<br/>timetable_db

    Officer->>UI: Enter credentials & login
    UI->>Kong: POST /api/v1/auth/login
    Kong->>Auth: Forward login request
    Auth->>Auth: Validate credentials (bcrypt)
    Auth-->>Kong: JWT access + refresh tokens
    Kong-->>UI: 200 OK + tokens
    UI-->>Officer: Redirect to dashboard

    Officer->>UI: Open Generate Timetable form<br/>(dept, semester, template)
    UI->>Kong: POST /api/v1/timetable/generate<br/>Authorization: Bearer JWT
    Kong->>Kong: Validate JWT plugin
    Kong->>TT: Forward generate request

    TT->>TT: Authorize role<br/>(admin | timetable_officer)
    TT->>DB: SELECT courses, rooms, lecturers,<br/>time_slots, constraints
    DB-->>TT: Scheduling dataset

    TT->>DB: SELECT active cross-dept bookings
    DB-->>TT: External room/lecturer bookings

    TT->>GA: run_ga(courses, rooms, slots, lecturers, constraints)
    loop Each generation until threshold or max_gen
        GA->>GA: Tournament select → crossover → mutate
        GA->>GA: Parallel fitness evaluation<br/>(ThreadPoolExecutor)
    end
    GA-->>TT: GAResult (best chromosome, fitness, violations)

    TT->>DB: INSERT timetable + timetable_entries
    DB-->>TT: Persisted timetable ID

    TT-->>Kong: 201 Created + timetable JSON
    Kong-->>UI: Response with entries
    UI-->>Officer: Display generated timetable grid
```

## Secondary Sequence — AI Dynamic Adjustment (Sora)

```mermaid
sequenceDiagram
    autonumber
    actor Officer as Timetable Officer
    participant UI as Vue 3 Frontend
    participant Kong as Kong Gateway
    participant Adj as adjustment-engine<br/>(:5003)
    participant Sora as LangGraph Agent<br/>(Sora)
    participant TT as timetable-engine
    participant Redis as Redis<br/>(pub/sub)
    participant Chroma as ChromaDB

    Officer->>UI: "Lecturer X is sick — find substitute"
    UI->>Kong: POST /api/v1/adjustments/sessions/{id}/chat
    Kong->>Adj: Forward (JWT validated)

    Adj->>Adj: Create / resume session
    Adj->>Chroma: Retrieve relevant past context
    Adj->>Sora: Invoke agent graph with user message

    Sora->>TT: GET timetable entries<br/>(X-Internal-Service-Key)
    TT-->>Sora: Session list

    Sora->>TT: GET available lecturers
    Sora->>TT: detect_timetable_conflicts
  alt Multiple substitute candidates
        Sora->>Adj: ask_user (interrupt)
        Adj->>Redis: Publish SSE event
        Redis-->>UI: Stream "awaiting decision"
        Officer->>UI: Select replacement lecturer
        UI->>Adj: POST /sessions/{id}/respond
        Adj->>Sora: Resume with human choice
    end

    Sora->>TT: substitute_lecturer(sick_id, replacement_id)
    TT->>TT: Update all affected entries
    TT-->>Sora: Substitution complete

    Sora-->>Adj: Final response + tool trace
    Adj->>Redis: Publish completion events
    Redis-->>UI: SSE stream updates
    UI-->>Officer: Show resolution summary
```
